Split Pane Tweet Composer + Agent Plan

Build the smallest useful app: an official-looking local composer on the left, and a Cloudflare Sandbox-backed coding agent on the right.

Why the chat HTML did not render

The Workbench chat escaped my assistant HTML as text. HTML in a message is not a trusted render surface in this path, especially when mixed near workflow/task notification output. A real .html file artifact is the right render target.

Implementation phases

  1. Create app folder: create poaster-app/ under /Users/anishthite/workspace/poaster.
  2. Left pane: build an X-style local tweet composer with avatar, textarea, character count, action row, and blue post button.
  3. Tweeted preview: render a local X-style posted-card preview from the draft immediately.
  4. Official X posting: open https://twitter.com/intent/tweet?text=... for actual posting.
  5. Official X embed: if the user pastes a real public tweet URL, render it with X widgets/oEmbed.
  6. Right pane: add an agent chat panel with transcript, prompt box, start/stop buttons, status, and streamed output.
  7. Backend: port Board’s Cloudflare Sandbox setup, trimmed to session creation, start/stop, and pi streaming.
  8. Runtime: copy Board’s sandbox runtime shape, but use a slim Poaster-specific pi-runner.js.
