Summary

GoalBuild poaster-app/ with an X-style composer and a Cloudflare Sandbox-backed agent.
SourceUser asked for a subfolder app, official-looking tweet UI, tweeted preview, and Board-style Sandbox agent.
Surfacesrc/*, server/*, worker/*, sandbox-runtime/*, wrangler.toml.
APIPOST /api/agent/sessions, /start, /stop, /pi/stream.
SchemaNo DB; session id maps deterministically to poaster-<id>.
Open Qs0; defaults applied from the plan.

API contract

POST /api/agent/sessions {}
→ { session: { id, provider, providerSessionId, status, cwd, errorMessage } }

POST /api/agent/sessions/:id/pi/stream { message, draft, postedPreview, tweetUrl }
→ text/event-stream events: status | stdout | stderr | done | error

UI layout

  1. Left pane renders local X-style composer, intent link, local posted card, and optional real tweet embed.
  2. Right pane renders agent transcript, sandbox controls, status line, and streaming answer.

Decisions

IDChoiceRationale
D-001Use poaster-app/.The plan picked this default; it avoids literal duplicated repo nesting.
D-002Use native DOM + Vite.React adds no value for one page.
D-003Keep agent sessions stateless server-side.Deterministic sandbox ids avoid D1 for the MVP.
D-004Use Web Intent for posting.X exposes official intent links, not an embeddable composer.

Tradeoffs

IDPicked over RejectedReason
T-001Local posted preview over fake official iframe.X compose iframes are not a supported component.
T-002Direct Worker router over Hono.Four endpoints do not need a framework.

Assumptions

  • A-001: Agent persistence across reloads is not required for the first build.
  • A-002: The agent helps with the post/page from inside the sandbox; it does not mutate the local host repo.
