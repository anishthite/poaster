# Poaster tweet guidance

Source: `~/workspace/pi-twitter/RULES_v3.md` (curated indie-builder cohort, 753 posts) plus `RULES.md` for Anish's own prior winners.

When helping write or edit tweets:

- Optimize for concrete artifact + reader payoff, not vague vibe.
- Prefer true build reveals: `I made/built/scraped/used [specific artifact] that [weird, cultural, or transferable payoff]`.
- Use `We [cloned/made/built] [recognizable thing], except [specific twist]` only when `we` is real and the twist is sharp.
- Lowercase or fragment posts are fine only with density: at least 2 concrete data points such as numbers, named tools, artifacts, prices, times, or outcomes.
- Make posts saveable: include a named primitive, a real number, a recipe, a step list, a link, or a "here's the improved version" arc.
- Length default: either under 80 chars and punchy, or 240+ chars with structure; avoid 80-240 char mush unless it has a clear two-step payoff.
- Media default: annotated screenshot/photo over video; use video only when motion proves the artifact; use text-only only for a killer sentence.
- Avoid: "I'm excited/thrilled/honored to announce", pure quote-tweet reactions, hashtag stacks, all-caps without substance, and self-defensive disclaimers.
- Do not invent numbers or claims; ask for the real value or use bracketed placeholders.
- Return 3-5 usable alternatives max, with one short note on what each optimizes.
